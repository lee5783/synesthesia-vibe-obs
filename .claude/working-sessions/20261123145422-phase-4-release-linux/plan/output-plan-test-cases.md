# Test cases

These are scenario-level expectations for manual QA, not scripts, and not a request for automated tests.

- **CI and Release rows (TC-C\*, TC-R\*)** are judged from GitHub Actions runs and the Releases page. They need the push/tag permission in C-001.
- **macOS rows (TC-M\*)** are judged on this Mac.
- **Linux runtime rows (TC-L\*)** need a real Ubuntu machine, and only the user can run them (P4-008).

| ID | Component / area | Preconditions | Expected |
|----|--------------------|---------------|----------|
| TC-C01 | `ci.yaml` → `build-plugin.yaml`, macOS job | A PR, or a push on a trigger from C-003; cold caches | The job goes green. It uploads `synesthesia-vibe-obs-<ver>-macos-arm64.pkg` and `.zip`. The inspection step shows `hostArchitectures="arm64"`, `lipo` arm64 only, exactly the 7 `obs_module_*` exports, a valid deep/strict `codesign` verify with `Signature=adhoc`, and no `.milk` or texture files in the payload. The cold wall time is recorded. |
| TC-C02 | CI caching (`plugin/.deps/`, vcpkg archives) | A second run on the same commit or buildspec | The libobs/obs-deps step and the vcpkg install restore from cache; the libobs build is skipped. The warm wall time is noticeably lower than TC-C01's and is recorded. |
| TC-C03 | `build-plugin.yaml`, Linux job (ubuntu-24.04) | The same trigger; P4-003, P4-004 and P4-005 merged on the branch | The job goes green. The `.so` exports exactly the 7 `obs_module_*` names, with no `glad*`, `sv_*`, projectM or C++ weak symbols. `ldd` shows nothing `not found`. The `dlopen` probe resolves `obs_module_load`. The libobs version used is printed. |
| TC-C04 | Linux `.deb` artifact | TC-C03 green | `dpkg-deb -c` lists `/usr/lib/x86_64-linux-gnu/obs-plugins/synesthesia-vibe-obs.so` and `/usr/share/obs/obs-plugins/synesthesia-vibe-obs/locale/en-US.ini`, with no presets or textures. `dpkg-deb -I` shows a non-empty Maintainer (C-008) and a Depends line that names the OBS/libobs package. |
| TC-C05 | Workflow security posture | All workflow files on the branch | Every `uses:` is pinned to a 40-char SHA. Build jobs have `contents: read`; only the release job has `contents: write`. No `secrets.*` is referenced. `actionlint` is clean. No machine paths or emails appear in YAML. |
| TC-C06 | PR from a fork, or a PR without secrets | A PR event | The builds run and pass without any secret. Nothing tries to sign with a Developer ID or notarize. |
| TC-C07 | CI build number | A CI run (P4-001) | The built macOS `Info.plist` `CFBundleVersion` equals the run's `GITHUB_RUN_ID`, not `1`. |
| TC-R01 | `release.yaml`, valid prerelease tag | A tag such as `v0.1.0-beta.1` matching buildspec `0.1.0` (only with C-001 permission) | The workflow builds in Release. It creates a **draft prerelease** named `SynesthesiaVibe Visualizer 0.1.0-beta.1` with the macOS pkg, the zip, `SHA256SUMS.txt`, and the Linux `.deb` only if C-006 allows it. The notes say unnotarized/ad-hoc (with the install link), name core `v0.7.0` and the Linux status, and link the source. Nothing is published until a human publishes the draft. |
| TC-R02 | `release.yaml`, version mismatch | A tag `v0.2.0` while buildspec says `0.1.0` (dry run of the validation logic, or a real tag with permission) | Validation fails before any build job starts, with a message naming both versions. No release is created. |
| TC-R03 | `release.yaml`, wrong tag shape | Tags `0.1.0`, `v0.1`, `v0.1.0-foo` | `0.1.0` does not trigger the workflow (the trigger is `v*`). `v0.1` and `v0.1.0-foo` fail validation with a clear message. |
| TC-R04 | `release.yaml`, plain final tag | A tag `v0.1.0` | Behaves as C-016 decides. Either it is refused while the Phase 2 gate is open, or it becomes a draft non-prerelease. Either way no release is published automatically. |
| TC-R05 | Release checksums | A draft from TC-R01 | `shasum -a 256 -c SHA256SUMS.txt` passes on the downloaded assets. |
| TC-M01 | macOS local build after the OS split (P4-003, P4-004) | This Mac, `cmake --preset macos-arm64` fresh | The configure passes on the first try, the build is clean under `-Werror`, `nm -gU` shows the same 7 names, and `otool -L` and the GL imports are unchanged from before Phase 4. |
| TC-M02 | Build guard, macOS | This Mac | `cmake --preset macos` and a `-G Ninja` configure both still fail with the (updated) guard message, and `.CMakeBuildNumber` is unchanged. |
| TC-M03 | macOS runtime smoke in OBS | OBS usable with obs-websocket (C-024), a test scene collection, plugin installed from the local or CI build | The log shows `renderer check passed (OpenGL, device type 1)` and `sv_init_gl and sv_create succeeded`. A preset animates next to an image, colour and text source. There are 0 GL error lines, and quitting reports `Number of memory leaks: 0`. |
| TC-M04 | macOS pkg from CI | The CI pkg artifact downloaded (optional, user-approved install) | `installer -pkg … -target CurrentUserHomeDirectory` puts the bundle in `~/Library/Application Support/obs-studio/plugins/` and OBS loads it as in TC-M03. This also covers the Phase 2 "pkg install not verified" follow-up. |
| TC-L01 | Linux install (`.deb`) | Ubuntu 24.04 x86_64, OBS from the PPA at or above the CI libobs version, X11 session | `sudo apt install ./synesthesia-vibe-obs-<ver>-x86_64-linux-gnu.deb` succeeds. After an OBS restart the log shows the renderer check pass line, the platform line (X11/EGL), and `plugin loaded successfully`. "SynesthesiaVibe Visualizer" is in Add Source. |
| TC-L02 | Linux render and GL state, X11 | TC-L01, a preset folder picked (dev-only presets outside the repo) | The preset animates the right way up and opaque. Image, colour and text sources in the same scene still draw correctly through scene switches and show/hide. The OBS log has no GL error lines. |
| TC-L03 | Linux audio | TC-L01, an audio source (PulseAudio/PipeWire input or a Media Source) | The visualizer reacts to the chosen source and to the whole mix on the chosen track, and stays still in silence. |
| TC-L04 | Linux presets, hotkeys, settings | TC-L01 | Preset change, auto-cycle, blend and the four hotkeys work without restarting OBS. Opening the properties dialog does not wedge OBS (`common-issues/verification-tooling.md` rule respected). |
| TC-L05 | Linux teardown | TC-L01 | Removing the source and quitting OBS do not crash, and the log ends with `Number of memory leaks: 0`. |
| TC-L06 | Linux, Wayland session | The same machine logged into a Wayland session | TC-L01 to TC-L05 pass again. The platform log line says Wayland. |
| TC-L07 | Linux uninstall | After TC-L06 | `sudo apt remove synesthesia-vibe-obs` removes the `.so` and the data folder, and OBS starts cleanly without the source. |
| TC-L08 | Flatpak OBS (negative) | OBS installed from Flathub | The `.deb` does not load into Flatpak OBS. The README says so (C-010), and nothing crashes. |
| TC-D01 | `plugin/README.md` | After P4-007 | Every asset name, path and command matches the CI artifacts and the `dpkg-deb -c` listing. The Linux status wording matches C-006. The macOS sections are unchanged apart from *Download*. |
| TC-D02 | `docs/` sync | After P4-012 | `docs/integrations.md` describes the workflows, triggers, caches, release flow and Linux packaging. The seed debt is marked resolved in `docs/concerns.md`. `docs/README.md` and the `CLAUDE.md` table list only pages that exist. |
