# P2-012 — 1080p60 measurement

Run on 2026-11-23 in session A of the P2-011 run (`../P2-011/P2-011-done-when.md`), on the
production build of `4c260b5`. C-001 was approved in Phase 2: use a separate profile, and leave
the user's own profile untouched.

**Result: pass.**
- `activeFps` held 60 in all 30 samples.
- `averageFrameRenderTime` stayed between 3.75 and 8.60 ms (median 4.69 ms), against the 16.7 ms
  budget.
- One frame was skipped in 17 446.

## Procedure

1. Checked that no stream, recording or virtual camera was running.
2. `CreateProfile synesthesia-1080p60`: OBS logged `Created profile 'synesthesia-1080p60' (clean)`.
3. `SetVideoSettings`: base and output 1920×1080, 60/1 fps (`video settings reset` in the log).
4. Created a scene `RT 1080p60` holding the visualizer at (0, 0), scale 1, and `RT Beat`.
   Visualizer settings: 1920×1080, render scale 100 %, audio attached, auto-cycle every 10 s,
   blend 2.7 s.
5. Sampled `GetStats` every 10 s for 300 s (30 samples, 291 s between the first and last).
6. Removed the scene, switched back to `Untitled` (1080×1920, 30 fps, confirmed by
   `GetProfileList` and `GetVideoSettings`), then removed the temporary profile.

## Numbers

| Metric | Value |
|---|---|
| `activeFps` | 60 in every sample |
| `averageFrameRenderTime` | min 3.75 ms, median 4.69 ms, max 8.60 ms |
| `renderSkippedFrames` | 2 → 3 (one frame, between t = 80 s and t = 90 s) |
| Frames rendered | 17 446 in 291 s |
| Preset commits in the window | 24. The 4 slowest took 15.0, 18.3, 19.5 and 20.7 ms (all with a 2.7 s blend). |
| GL error lines | 0 |

**What it means for the open concern.** The concern was that a heavy commit of about 18 ms, run
inside `video_render`, would cost frames at 60 fps (`docs/concerns.md`). Commits did reach
20.7 ms here, and auto-cycle every 10 s ran 24 blends, but only one frame was skipped in 5
minutes. 75 % and 50 % render scale were not needed.
