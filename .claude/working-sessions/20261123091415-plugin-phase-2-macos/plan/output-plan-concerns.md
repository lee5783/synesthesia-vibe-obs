| C-002 | question | Signed + notarized `.plugin` has no credentials | `security find-identity -p codesigning -v` lists only **Apple Development** and **Apple Distribution** identities, and no **Developer ID Application** or **Developer ID Installer**. The notarization commands (`productsign`, `notarytool submit --wait`, `stapler staple`) are documented and run only when the user supplies a Developer ID identity and a notarytool keychain profile, outside the repo and through environment variables. PLAN item 7 stays "partly done: notarization blocked on credentials". Alternative: the user creates Developer ID certificates now. | *(pending — user / orchestrator)* |

| C-004 | unclear_requirement | Behaviour with no preset folder, or an empty one | With no bundled presets (C-003), a new source has nothing to load. | C-005 | question | How the chosen audio source is stored | By name is OBS's own sidechain convention (`compressor-filter.c`) and survives copying a scene collection between machines, but breaks on rename. By UUID (`obs_get_source_by_uuid`, available in libobs 31) survives renames but not a source deleted and re-created. Either way the source may not exist yet when the visualizer is created (scene collection load order). | **Default:** store the **UUID**, show the name as the list label, and resolve lazily in `video_tick` (throttled to about 1 s) until found. If the UUID is gone, the list shows "(missing)" and audio is silent. Alternative: by name, like the sidechain. | *(pending — user / orchestrator)* |
| C-006 | edge_case | The core's PCM buffer is process-global | `sv_push_pcm_float(ctx, …)` ignores `ctx`'s identity for storage: `SetAudioBuf` writes the global `pcmLeftLpb`/`pcmRightLpb` (mutex-guarded) in `src/audio/audiobuf.cpp`. **Two visualizer instances with different audio sources would both react to the mixed samples of both.** The same input in two instances is pushed twice (harmless). This can't be fixed in the plugin. | **Default:** document the limit ("one audio input per OBS instance; multiple visualizers share audio analysis") in `plugin/README.md` and `docs/concerns.md`. Draft **upstream ask #4** in the doc pass: a per-context PCM buffer, plus a sample-rate parameter (C-007). Don't block Phase 2. | *(pending — user / orchestrator)* |
| C-007 | edge_case | Sample rate | `sv_push_pcm_float` labels all samples as 44,100 Hz (`TARGET_SAMPLE_RATE`); OBS usually runs at 48 kHz. Pushing 48 kHz raw skews the frequency analysis by about 8.8 %. libobs can convert: `audio_output_connect` takes an `audio_convert_info` (rate, format, layout) for the mix path, and `audio_resampler_*` (exported) handles per-source capture. | **Default:** convert to 44.1 kHz interleaved stereo float on the audio side before the ring. Mix path: `{44100, AUDIO_FORMAT_FLOAT, SPEAKERS_STEREO}`. Per-source path: one `audio_resampler` per attachment. Alternative: push raw and accept the skew. | *(pending — user / orchestrator)* |
| C-008 | question | Muted audio source | `obs_source_audio_capture_t` gets `muted`. The whole mix already excludes muted sources. The spec doesn't say whether a muted chosen source should still drive the visuals. | **Default:** muted means silence, matching what the stream hears. | *(pending — user / orchestrator)* |
| C-009 | error_case | TSan can't verify the race fix against release OBS | `/Applications/OBS.app` has hardened runtime with only `disable-library-validation` and `allow-unsigned-executable-memory`, and no `allow-dyld-environment-variables`. So `DYLD_INSERT_LIBRARIES` is stripped and the macOS TSan runtime can't be injected. Building OBS itself with TSan is a large detour. | **Default:** verify with (1) code review of the threading contract, (2) a temporary re-entrancy detector (an atomic in-flight counter around core calls, logging overlaps) in a scratch build, and (3) a 5-minute `GetSourceScreenshot` stress loop on air (P2-002, P2-011). Remove the instrumentation before review. Alternative: build OBS from source with TSan, which needs explicit approval and time. | *(pending — user / orchestrator)* |
| C-010 | question | Evidence that audio drives the visuals | Screenshots alone don't prove reaction. The core offers `sv_set_debug_callback` with bass/mid/treb. A permanent periodic log would break the "nothing per frame / one line per decision" convention. | **Default:** a temporary debug callback in a scratch build logs levels once a second for muted-vs-unmuted comparisons, and is removed before review. No user-facing debug setting in Phase 2. Alternative: a hidden opt-in "debug log" setting kept in the product. | *(pending — user / orchestrator)* |
