# Codebase Structure

**Analysis Date:** 2026-11-23

## Directory Layout

│   ├── fetch-dist.sh          # installs the core web dist + presets into dist/

│   └── dist/                  # generated by fetch-dist.sh, git-ignored

## Directory Purposes

**`browser-source/`:**
- Purpose: everything OBS's Browser Source loads, plus the script that fetches the core.
- Contains: one HTML file, one ES module, one Bash script, the user README.
- Key files: `browser-source/obs-page.js`, `browser-source/fetch-dist.sh`.

**`browser-source/dist/`** (generated):
- `synesthesia-vibe.js` + the dist's other modules and WASM (from the release zip), `LICENSE`,
  `NOTICE`, `VERSION` (core's), `resources/presets/*.milk`, `resources/textures/*`,
  `resources/manifest.json`.

**`plugin/`:**
- Purpose: the native plugin, on the `obsproject/obs-plugintemplate` layout pinned at
  `3e7d7ac3b5342cd7d9b88890b9c70b472d1520fc`.
- **Verbatim template files** (vendored, no header added, comments kept, byte-identical to the
  pinned commit): `plugin/cmake/**`, `plugin/src/plugin-support.c.in`,
  `plugin/src/plugin-support.h`. Do not edit them; work around template bugs from
  `plugin/CMakeLists.txt` instead.
- **Authored files** (carry the standard header): `plugin/CMakeLists.txt`,
  `plugin/exported-symbols.txt`, `plugin/src/plugin-main.cpp`,
  `plugin/src/visualizer-source.cpp`, `plugin/src/visualizer-source.hpp`,
  `plugin/src/audio-ring.cpp`, `plugin/src/audio-ring.hpp`, `plugin/data/locale/en-US.ini`,
  `plugin/packaging/macos/distribution.in` (header as an XML comment after the XML declaration).
  `plugin/CMakePresets.json` and `plugin/buildspec.json` are template files with authored edits
  (the `macos-arm64` preset; the plugin identity).
- **User page:** `plugin/README.md` (no file header, README convention). Install from the pkg or
  zip, the OpenGL check, settings by group, hotkeys, presets and their terms, troubleshooting,
  uninstall. Developer build and packaging steps stay in `docs/integrations.md`.

**`plugin/packaging/macos/`:**
- Purpose: project-owned copies of template packaging inputs that this project must change.
  `distribution.in` is the template's `cmake/macos/resources/distribution.in` with
  `hostArchitectures="arm64"`. `plugin/CMakeLists.txt` configures it over the template's generated
  `build_macos_arm64/distribution` right after `set_target_properties_plugin`.
- It cannot live in `plugin/cmake/**` (template-only) or `plugin/data/**` (globbed into the
  bundle). Keep the per-OS segment (`packaging/windows/` etc. when Phase 3 needs one).

**`external/synesthesia-vibe/`:**
- Purpose: the core source, consumed by the plugin build only. The Browser Source does not need it.
- Never edit it. Bump it by checking out a new release tag and committing the gitlink.

## Key File Locations

**Entry Points:**
- `browser-source/index.html`: page entry, loads `obs-page.js`.
- `browser-source/obs-page.js`: `main()` at the bottom of the file.
- `plugin/src/plugin-main.cpp`: `obs_module_load` / `obs_module_unload`.

**Configuration:**
- `browser-source/fetch-dist.sh`: `PINNED_VERSION` (the one place the web dist version lives).
- `plugin/CMakePresets.json`, `plugin/buildspec.json`, `plugin/exported-symbols.txt`.
- `plugin/packaging/macos/distribution.in`: the pkg's Distribution XML (arm64 only, home domain).
- `.gitmodules` + the submodule gitlink: the plugin's core version.

**Core Logic:**
- `plugin/src/visualizer-source.cpp`: source callbacks and properties, `gl_state_guard`, render
  path, preset worker and auto-cycle, hotkeys, audio attachment.
- `plugin/src/audio-ring.cpp` / `.hpp`: the SPSC PCM ring between the audio callbacks and the
  render thread.
- `browser-source/obs-page.js`: settings parsing, preset matching, playlist, audio selection.

**Testing:**
- None in the repo. Verification evidence lives in session folders (see `docs/testing.md`).

## Naming Conventions

**Files:**
- kebab-case, letters/digits/hyphens: `obs-page.js`, `fetch-dist.sh`, `visualizer-source.cpp`,
  `audio-ring.cpp`.
- C++ headers use `.hpp` for authored code (`visualizer-source.hpp`, `audio-ring.hpp`); the
  vendored template header keeps `.h` (`plugin-support.h`).

**Directories:**
- kebab-case: `browser-source/`, `external/synesthesia-vibe/`. Doc trees mirror source paths
  segment for segment.

## Where to Add New Code

**Browser Source feature (new URL parameter, new behaviour):**
- Primary code: `browser-source/obs-page.js` (read it in `readSettings`, use it in `main`).
- User docs: the parameter table in `browser-source/README.md`.

**New plugin source behaviour (settings, audio, hotkeys):**
- Implementation: `plugin/src/visualizer-source.cpp`; register callbacks in
  `visualizer_source_register`. A new setting goes into the matching property group in
  `visualizer_get_properties` and gets a default in `visualizer_get_defaults`.
- A self-contained helper with its own state (like the ring): `plugin/src/<kebab-name>.cpp` /
  `.hpp`, added to `target_sources` in `plugin/CMakeLists.txt`. Follow `audio-ring.*` and
  `gl_state_guard` for class layout. The preset scheduler and the audio attachment are the next
  natural splits out of `visualizer-source.cpp` (about 1,290 lines).
- New user-visible strings: `plugin/data/locale/en-US.ini` (`docs/conventions.md`, *Strings*).
- User-facing behaviour changes: also update `plugin/README.md`.
- New `obs_module_*` entry point: also add it to `plugin/exported-symbols.txt`, or it is silently
  hidden.

**Build changes:**
- `plugin/CMakeLists.txt` only. Leave `plugin/cmake/**` verbatim.

**Packaging changes:**
- Copy the template file into `plugin/packaging/macos/` and configure it from
  `plugin/CMakeLists.txt` to the same output path the template uses, after
  `set_target_properties_plugin`. Check the generated file after configure
  (`docs/integrations.md`, *Packaging*).

**Docs:**
- `docs/<page>.md`, listed in `docs/README.md` and the `CLAUDE.md` routing table.

## Special Directories

**`browser-source/dist/`:**
- Purpose: core web dist, presets, textures, manifest.
- Generated: Yes (`fetch-dist.sh`). Committed: No (presets are local-use only).

**`browser-source/.dist-stage.*`, `browser-source/.dist-old.*`:**
- Purpose: temporary staging during `fetch-dist.sh`; removed by its trap. Can survive a
  `SIGKILL`. Generated: Yes. Committed: No (not git-ignored; delete by hand if seen).

**`plugin/.deps/`:**
- Purpose: obs-studio 31.1.1 source/libobs build, obs-deps and Qt6 prebuilts.
- Generated: Yes (first configure, about 3 min). Committed: No.

**`plugin/build_macos_arm64/`:**
- Purpose: Xcode build tree. Holds `RelWithDebInfo/synesthesia-vibe-obs.plugin` (dev build),
  `Release/` (release build plus `.dSYM`), the generated `distribution`, and the core's inner build
  at `synesthesia-vibe-core/build/` with its install prefix at `synesthesia-vibe-core/install/`
  (`lib/libSynesthesiaVibeCore.a`, `include/`).
- Generated: Yes. Committed: No.

**`plugin/build_macos_arm64/package-staging/`:**
- Purpose: the `--prefix` of `cmake --install`: the staged `.plugin` and `.plugin.dSYM`, the
  unsigned `synesthesia-vibe-obs.pkg`, and the release zip made with `ditto`.
- Never name it `release`: on a case-insensitive volume that is Xcode's `Release/` folder
  (`.claude/common-issues/plugin-build.md`).
- Generated: Yes. Committed: No.

**`plugin/build_macos/`:**
- Purpose: a stub tree (`CMakeCache` only) left by a configure the build guard refused. Safe to
  delete. Generated: Yes. Committed: No (`plugin/build_*/`).

**`plugin/cmake/.CMakeBuildNumber`:**
- Purpose: template build counter, seeded with `0` by `plugin/CMakeLists.txt` on first configure.
- Generated: Yes. Committed: No.

**`.claude/working-sessions/<timestamp>-<slug>/`:**
- Purpose: vibe-flow session artifacts (`input-*.md` / `output-*.md`) and evidence.
- Committed: only `.md` and `.py` files under `develop/evidence/`; images, logs and helper
  scripts there are git-ignored (`.gitignore`).
